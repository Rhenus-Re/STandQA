# 对象与矩阵缺陷补充记录

本记录补充对象与矩阵测试域的 B-04、B-05 缺陷证据。被测版本为 `python-qrcode v8.2`，执行环境为 Python 3.12.14。

## B-04：自动适配超出版本上限时抛出错误异常类型

| 项目 | 内容 |
|---|---|
| 类别 | 对象版本适配与异常行为 |
| 严重程度 | 中：调用者无法按 `DataOverflowError` 处理容量不足 |
| 回归用例 | `TC-B-13` |
| 受影响源码 | `qrcode/main.py::QRCode.best_fit` |
| 公开来源 | 上游 Issue [#322](https://github.com/lincolnloop/python-qrcode/issues/322) |
| 测试提交 | `b59786a` |
| 修复提交 | `fbcee7b` |

最小复现：

```python
qr = QRCode()
qr.add_data(b"A" * 5000)
qr.make()
```

修复前，自动适配查找得到的候选版本为 41。代码先把该值写入 `version` 属性，属性校验立即抛出：

```text
ValueError: Invalid version (was 41, expected 1 to 40)
```

但版本 41 在这里不是用户输入错误，而是“数据无法放入最大版本 40”的内部哨兵值；公开 API 应抛出 `DataOverflowError`，让调用者可与固定版本容量不足时保持一致地处理。

修复将候选版本保存在局部变量，先判断是否为 41；若是则抛出 `DataOverflowError`，否则再赋值给 `self.version`。修复后 `TC-B-13` 通过，5000 字节输入正确报告 `DataOverflowError`。

## B-05：切换显式版本后复用旧编码缓存

| 项目 | 内容 |
|---|---|
| 类别 | `QRCode` 对象状态与重新编码行为 |
| 严重程度 | 高：生成版本 2 矩阵时映射版本 1 的码字，结果与同条件新建对象不一致 |
| 回归用例 | `TC-B-14` |
| 受影响源码 | `qrcode/main.py::QRCode.version` |
| 发现方式 | 通过 `QRCode` 正常公开接口的场景复现 |
| 测试提交 | `8522910` |
| 修复提交 | `e3ff495` |

最小复现：

```python
from qrcode import QRCode, constants

qr = QRCode(version=1, error_correction=constants.ERROR_CORRECT_L)
qr.add_data("cache-change")
qr.make(fit=False)
qr.version = 2
qr.make(fit=False)
```

修复前，第一次生成后的 `data_cache` 有 26 个码字；通过公开属性把 `version` 改为 2 并再次生成后，缓存仍是 26 个码字。以相同数据新建版本 2 对照对象时，正确缓存应有 44 个码字。两者的编码缓存和最终矩阵均不相同。

根因是编码缓存同时依赖版本容量和 RS 纠错块配置，但 `version` 属性的 setter 只更新 `_version`，未废弃已计算的 `data_cache`。后续 `make()` 因缓存非空而跳过重新编码，于是版本 2 的模块映射逻辑读取了版本 1 的码字。

修复在版本值实际发生变化时将 `data_cache` 设为 `None`，使下一次 `make()` 重新计算编码与纠错码字。修复后 `TC-B-14` 通过：切换后的缓存长度为 44，且缓存和最终矩阵均与相同条件的新建版本 2 对照对象一致。
