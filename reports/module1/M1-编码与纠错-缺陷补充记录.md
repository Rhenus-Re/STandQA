## A-02：零值 RS 数据块触发 `glog(0)`

| 项目 | 内容 |
|---|---|
| 类别 | 编码与 Reed–Solomon 纠错 |
| 严重程度 | 高：合法二进制输入无法生成二维码 |
| 回归用例 | `TC-A-10` |
| 受影响源码 | `qrcode/base.py::Polynomial.__mod__` |
| 公开来源 | 上游 Issue [#330](https://github.com/lincolnloop/python-qrcode/issues/330)、[#423](https://github.com/lincolnloop/python-qrcode/issues/423) |
| 测试提交 | `ac7c640` |
| 修复提交 | `f4bcf02` |

最小复现：

```python
qr = QRCode(version=5, error_correction=constants.ERROR_CORRECT_Q)
qr.add_data(b"\x00" * 28)
qr.make(fit=False)
```

修复前，`make()` 抛出 `ValueError: glog(0)`；修复后正常生成版本 5 的二维码，`data_cache` 包含 134 个码字。边界对照中，27 个零字节可生成，28 个零字节在修复前失败。

根因是版本 5、Q 级纠错把数据分为多个 RS 块。该输入使其中一个数据块的多项式系数全为零；旧的取余实现直接计算 `glog(self[0])`，而有限域中 `glog(0)` 无定义。修复在取余时消去零首项并继续递归计算，使零多项式得到正确的零余数与零纠错字节。

## A-03：自动掩码评分未包含完整二维码

| 项目 | 内容 |
|---|---|
| 类别 | 掩码选择与惩罚评分 |
| 严重程度 | 中：自动选择的掩码并非最终二维码的最低惩罚分掩码 |
| 回归用例 | `TC-A-12` |
| 受影响源码 | `qrcode/main.py::QRCode.best_mask_pattern`、`qrcode/util.py::lost_point` |
| 公开来源 | 上游 PR [#389](https://github.com/lincolnloop/python-qrcode/pull/389)（修复完整符号评分） |
| 测试提交 | `ac7c640` |
| 修复提交 | `f4bcf02` |

最小复现数据：

```python
data = b"https://example.com/a?b=1"
qr = QRCode(error_correction=constants.ERROR_CORRECT_M)
qr.add_data(data)
```

修复前，`best_mask_pattern()` 选择掩码 5；将八种掩码按最终二维码完整生成后，惩罚分依次为：

```text
掩码编号：0    1    2    3    4    5    6    7
惩罚评分：563  422  419  597  506  530  491  658
```

因此正确最低分为掩码 2（419），旧选择掩码 5（530）。

根因是 `best_mask_pattern()` 用 `makeImpl(True, mask)` 构造候选矩阵；测试标志使格式信息、版本信息和固定深色模块不使用真实值，但 `lost_point()` 随即对这个不完整矩阵评分。修复改为以完整矩阵 `makeImpl(False, mask)` 评分，保证评分对象与最终输出二维码一致。
